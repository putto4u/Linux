중앙 집중형 DNS 서버인 **BIND9**을 구축하면 100대의 PC를 일일이 관리할 필요 없이 서버 한 곳에서 모든 네트워크 이름을 제어할 수 있습니다. 각 설정 파일의 모든 행에 상세한 주석을 포함하여 재구성하였습니다.

---

## BIND9 설치 및 상세 설정 (모든 행 주석 포함)

### 1. 패키지 설치

먼저 시스템을 업데이트하고 DNS 서비스에 필요한 패키지들을 설치합니다.

```bash
sudo apt update && sudo apt install -y bind9 bind9utils

```

---

### 2. 전역 옵션 설정 (`/etc/bind/named.conf.options`)

DNS 서버의 접근 권한과 외부 질의 전달(Forwarding)을 정의합니다.

```bash
sudo vi /etc/bind/named.conf.options

```

```text
acl "trusted" {                         # 'trusted'라는 이름의 접근 제어 목록 정의
        192.168.1.0/24;                 # 우리 사내망 IP 대역 (100대 PC가 속한 대역)
};                                      # ACL 정의 종료

options {                               # 전역 옵션 시작
        directory "/var/cache/bind";    # DNS 캐시 및 작업 데이터가 저장되는 디렉터리

        recursion yes;                  # 내부 PC를 대신해 외부 주소를 찾아주는 재귀 쿼리 허용
        allow-query { trusted; };       # 위에서 정의한 'trusted' 대역의 PC만 질의 허용 (보안)

        forwarders {                    # 사내망에 없는 주소(예: google.com)를 물어볼 외부 DNS
                8.8.8.8;                # Google 주 DNS
                8.8.4.4;                # Google 보조 DNS
        };                              # 포워더 설정 종료

        dnssec-validation auto;         # DNS 응답의 위변조 방지를 위한 보안 서명 검증 활성화
        listen-on-v6 { any; };          # IPv6 주소에 대한 질의도 모든 인터페이스에서 허용
};                                      # 옵션 설정 종료

```

---

### 3. 도메인 영역 정의 (`/etc/bind/named.conf.local`)

우리가 관리할 도메인 이름과 해당 데이터를 담은 파일 경로를 연결합니다.

```bash
sudo vi /etc/bind/named.conf.local

```

```text
zone "internal.com" {                   # "internal.com"이라는 이름의 도메인 영역 설정
    type master;                        # 이 서버가 해당 도메인의 주(Master) 서버임을 명시
    file "/etc/bind/db.internal.com";   # 실제 호스트 IP 정보가 담긴 데이터 파일 경로
};                                      # 영역 설정 종료

```

---

### 4. 영역 데이터 파일 작성 (`/etc/bind/db.internal.com`)

도메인 내의 개별 서버 IP들을 등록하는 가장 핵심적인 파일입니다.

```bash
sudo cp /etc/bind/db.local /etc/bind/db.internal.com # 기본 템플릿 복사
sudo vi /etc/bind/db.internal.com

```

```text
$TTL    604800                          # DNS 레코드 정보가 클라이언트에 캐싱되는 시간 (초)
@       IN      SOA     ns1.internal.com. admin.internal.com. ( # 인증 권한 시작 및 관리자 메일
                              3         ; Serial  (파일 수정 시마다 숫자를 올려야 보조서버가 갱신됨)
                         604800         ; Refresh (보조 서버가 주 서버 정보를 확인하는 주기)
                          86400         ; Retry   (정보 확인 실패 시 재시도 주기)
                        2419200         ; Expire  (주 서버 응답 없을 때 데이터 폐기 전 유지 기간)
                         604800 )       ; Negative Cache TTL (존재하지 않는 도메인 응답의 캐시 시간)
;
@       IN      NS      ns1.internal.com. # 이 도메인을 관리하는 네임 서버의 이름 정의
ns1     IN      A       192.168.1.10    # 네임 서버(본인)의 호스트 이름과 IP 매핑
web     IN      A       192.168.1.100   # 사내 웹서버: web.internal.com으로 접속 가능
db      IN      A       192.168.1.101   # 사내 DB서버: db.internal.com으로 접속 가능
storage IN      A       192.168.1.102   # 사내 파일서버: storage.internal.com으로 접속 가능

```

## 5. 설정 검증 및 서비스 활성화

오타 하나로 서비스가 중단될 수 있으므로 반드시 검증을 거칩니다.

```bash
sudo named-checkconf                    # 메인 설정 파일(/etc/bind/named.conf*) 문법 확인
sudo named-checkzone internal.com /etc/bind/db.internal.com # Zone 파일 데이터 정합성 확인

sudo systemctl restart bind9            # BIND9 서비스 재시작하여 변경 사항 적용
sudo systemctl enable bind9             # 시스템 부팅 시 자동으로 서비스 시작되도록 설정

```

## ⚠️ 클라우드 환경 및 인프라 운영 주의사항

* **방화벽 설정**: AWS EC2를 사용 중이라면 **Security Group(보안 그룹)**에서 **UDP/TCP 53번 포트**를 100대의 PC가 속한 IP 대역에 대해 반드시 개방해야 합니다.
* **상시 가동**: DNS 서버가 다운되면 사내의 모든 도메인 접속이 마비됩니다. 인스턴스 모니터링을 철저히 하십시오.
* **AWS 과금 알림**:
* 24시간 가동되는 BIND9용 EC2 인스턴스는 **인스턴스 유형에 따른 비용**이 발생합니다.
* 만약 이를 대체하기 위해 AWS의 **Route 53 Resolver(Inbound Endpoint)**를 사용하면, **시간당 약 $0.125(엔드포인트당)**의 비용이 발생하며 이는 직접 서버를 운영하는 것보다 비쌀 수 있으므로 비용 최적화가 필요합니다.
