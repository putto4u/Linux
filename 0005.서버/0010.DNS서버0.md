과거에는 `/etc/resolv.conf` 파일을 직접 수정하는 것만으로 충분했지만, 현대의 Ubuntu 시스템에서는 **Systemd-resolved** 서비스가 DNS 관리를 자동화하므로 직접 수정 방식은 권장되지 않습니다. 파일에 직접 작성하더라도 재부팅 시 초기화될 가능성이 높기 때문입니다.

사내 서버 주소를 등록하거나 자체 DNS 서버를 운영해야 하는 상황에 따른 최적의 방법을 정리합니다.

---

## 1. 사내 DNS 서버가 이미 있는 경우 (Client 설정)

사내에 이미 운영 중인 DNS 서버(예: 192.168.1.10)가 있다면, 새로운 DNS 서버를 구축할 필요 없이 **Netplan** 설정에 해당 IP를 추가하는 것이 가장 정확한 방법입니다.

### Netplan을 통한 사내 DNS 등록

`/etc/netplan/`에 있는 설정 파일을 수정하여 시스템이 항상 사내 DNS를 먼저 바라보게 합니다.

```yaml
      nameservers:
        addresses: 
          - 192.168.1.10    # [우선순위 1] 사내 DNS 서버 IP
          - 8.8.8.8         # [우선순위 2] 사내 DNS 장애 시 보조로 사용할 공용 DNS

```

* **적용**: `sudo netplan apply`
* **확인**: `resolvectl status` 명령어로 현재 시스템이 사용 중인 DNS 서버 목록을 확인합니다.

---

## 2. 특정 도메인만 사내 서버로 연결하고 싶은 경우 (`/etc/hosts`)

DNS 서버를 구축하거나 설정을 바꾸기 부담스럽고, **소수의 특정 서버(예: https://www.google.com/search?q=gw.internal.com)**만 IP와 매핑하고 싶을 때는 호스트 파일을 수정하는 것이 가장 빠릅니다.

* **파일 경로**: `/etc/hosts`
* **사용법**: `[IP주소] [도메인명]` 순으로 작성합니다.
```bash
192.168.1.50   my-database-server
192.168.1.60   internal-api.com

```


> 이 방식은 DNS 질의보다 우선순위가 높기 때문에, DNS 서버 없이도 즉시 이름 풀이가 가능합니다.



---

## 3. DNS 서버를 직접 구축해야 하는 경우 (Server 구축)

만약 사내에 수많은 서버가 있고, 이를 중앙에서 관리하거나 내부망 전용 도메인을 운영해야 한다면 **BIND9**와 같은 소프트웨어를 사용해 DNS 서버를 직접 구축해야 합니다.

### DNS 서버 구축이 필요한 상황

* 수십 대의 서버 IP를 일일이 `/etc/hosts`에 적기 힘든 경우
* `*.dev.company.com` 처럼 와일드카드 도메인 관리가 필요한 경우
* 내부 서비스의 부하 분산(Round Robin DNS)이 필요한 경우

---

## 4. 요약: 무엇을 선택해야 할까?

| 상황 | 권장 조치 | 난이도 |
| --- | --- | --- |
| **사내 DNS 서버 IP를 알고 있음** | **Netplan**의 `nameservers` 항목에 IP 추가 | 하 |
| **서버 1~2대만 이름으로 접속하고 싶음** | `/etc/hosts` 파일에 IP와 이름 수동 등록 | 하 |
| **독자적인 사내 도메인 체계 구축 필요** | **BIND9** 또는 **CoreDNS** 서버 구축 | 상 |

---

## ⚠️ 클라우드 환경 및 보안 주의사항

* **VPC DNS**: AWS 환경이라면 VPC 자체에서 제공하는 DNS 서비스(`Route 53 Resolver`)가 있습니다. 내부 설정을 복잡하게 바꾸기 전, 클라우드 콘솔에서 DNS 설정을 지원하는지 먼저 확인하는 것이 효율적입니다.
* **AWS 과금 관련**: 사내 서버를 AWS 위에서 운영하며 **Route 53 Private Hosted Zone**을 사용하여 DNS를 구성할 경우, 호스팅 영역당 **월별 고정 비용($0.50)**과 쿼리당 비용이 발생하므로 소규모 실습 시에는 `/etc/hosts` 방식을 권장합니다.

---

100대의 PC에 일일이 설정을 넣는 작업은 매우 고되지만, 상황에 따라 반드시 직접 파일을 수정해야 할 때가 있습니다. 각 운영체제(OS)별로 `hosts` 파일이 숨겨져 있는 경로와 수정 방법을 정리합니다.

---

## 운영체제별 `hosts` 파일 경로

모든 운영체제에서 `hosts` 파일은 시스템의 핵심 영역에 보호되어 있으므로, 반드시 **관리자 권한**이 필요합니다.

| 운영체제 (OS) | 파일 절대 경로 | 비고 |
| --- | --- | --- |
| **Windows 10/11** | `C:\Windows\System32\drivers\etc\hosts` | 메모장을 '관리자 권한'으로 실행 후 열기 |
| **Linux (Ubuntu 등)** | `/etc/hosts` | `sudo` 명령어를 사용하여 수정 |
| **macOS** | `/etc/hosts` | 터미널에서 `sudo nano` 등으로 수정 |

---

## OS별 상세 수정 절차

### 1. Windows (윈도우)

윈도우는 일반적인 방법으로 저장하려고 하면 "권한이 없습니다"라는 메시지가 뜹니다.

1. **시작 메뉴**에서 `메모장` 또는 `Notepad`를 검색합니다.
2. 마우스 오른쪽 버튼을 클릭하여 **[관리자 권한으로 실행]**을 선택합니다.
3. 메모장에서 **[파일] -> [열기]**를 누른 후 위 경로를 복사하여 붙여넣습니다.
4. 우측 하단의 파일 형식을 **[모든 파일 (*.*)]**로 변경해야 `hosts` 파일이 보입니다.

### 2. Linux / macOS

터미널을 실행한 후 텍스트 에디터(vi, nano 등)를 이용해 즉시 수정할 수 있습니다.

```bash
# vi 에디터 사용 시
sudo vi /etc/hosts

# nano 에디터 사용 시 (초보자 권장)
sudo nano /etc/hosts

```

---

## 파일 내용 기입 표준 형식

파일의 맨 아랫줄에 서버의 IP와 사내에서 부를 이름을 한 줄씩 추가합니다. (공백 또는 Tab으로 구분)

```text
# 사내 서버 IP 등록 (예시)
192.168.1.10    internal-web.com
192.168.1.20    db-server
192.168.1.30    file-storage

```

---

## ⚠️ 100대 PC 관리 시 주의사항 및 과금 리스크

1. **배포의 한계**: 100대의 PC에 이 파일을 수동으로 넣는 도중 오타가 발생하면 해당 PC만 특정 서버에 접속되지 않는 장애가 발생합니다.
2. **보안 프로그램 충돌**: 일부 백신(V3, 알약 등)이나 보안 소프트웨어는 `hosts` 파일 변조를 해킹으로 간주하여 수정을 차단하거나 원래대로 복구시킬 수 있습니다.
3. **클라우드 연동 시 (AWS)**:
* 만약 사내 PC들이 AWS에 있는 서버로 접속하는 상황이라면, 서버의 **Public IP** 대신 **Private IP**를 넣어야 하는지 명확히 구분해야 합니다.
* **AWS Private Link**나 **Route 53 Resolver** 같은 서비스를 연동하여 DNS를 자동화할 수 있지만, 이는 **시간당 엔드포인트 비용 및 처리량에 따른 유료 요금**이 발생하므로 100대 규모의 사내망 설계 시 예산 검토가 필요합니다.
