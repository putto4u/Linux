네트워크 설정은 서버 구축의 첫 단계이자 서비스 안정성을 결정짓는 가장 중요한 설정입니다. Ubuntu 18.04 LTS 버전부터 표준으로 채택된 **Netplan**을 중심으로, 정적 IP 설정 방법과 명령어, 주의사항을 통합하여 정리합니다.

---

## Ubuntu 네트워크 설정 가이드 (Netplan 기반)

Netplan은 YAML(Yet Another Markup Language) 형식을 사용하여 네트워크 인터페이스를 관리합니다. 기존의 `/etc/network/interfaces` 방식보다 구조적이며, 설정 변경 후 즉시 적용이 가능하다는 장점이 있습니다.

### 1. 인터페이스 식별 및 상태 확인

설정 전, 시스템이 인식하는 네트워크 장치의 논리적 이름을 확인해야 합니다.

```bash
# 네트워크 인터페이스 상세 정보 확인
ip addr

# 인터페이스 링크 상태만 확인
ip link show

```

> 출력 결과에서 `eth0`, `ens33`, `enp0s3` 등 본인의 환경에 맞는 이름을 반드시 메모해 두어야 합니다.

---

### 2. Netplan 설정 파일 구성 (정적 IP 할당)

Ubuntu의 설정 파일은 `/etc/netplan/` 경로 내에 `.yaml` 확장자로 존재합니다.

**설정 파일 편집:**

```bash
sudo vi /etc/netplan/01-netcfg.yaml

```

**YAML 파일 상세 주석 분석:**

```yaml
network:                                      # 네트워크 설정의 시작
  version: 2                                  # Netplan 구성 버전 (현재 v2 고정)
  renderer: networkd                          # 서버용 백엔드 엔진 (systemd-networkd)
  ethernets:                                  # 유선 이더넷 장치 설정 섹션
    ens33:                                    # [중요] 확인한 실제 인터페이스 이름 입력
      dhcp4: no                               # IPv4 자동 할당(DHCP) 사용 안 함
      addresses:                              # 할당할 고정 IP 주소 리스트
        - 192.168.1.100/24                    # [IP주소]/[서브넷마스크 CIDR]
      routes:                                 # 라우팅 경로(게이트웨이) 설정
        - to: default                         # 기본 경로 설정
          via: 192.168.1.1                    # 게이트웨이(Gateway) IP 주소
      nameservers:                            # DNS 서버 설정
        addresses: [8.8.8.8, 8.8.4.4]         # 기본/보조 DNS 서버 주소 (Google DNS)

```

---

### 3. 설정 적용 및 검증 절차

YAML 파일은 **들여쓰기(Indentation)**에 매우 민감합니다. 탭(Tab) 대신 공백(Space)을 사용해야 하며, 적용 전 검증 단계가 필수적입니다.

| 단계 | 명령어 | 주요 역할 |
| --- | --- | --- |
| **문법 검사** | `sudo netplan generate` | YAML 파일의 문법적 오류 여부만 체크 |
| **안전 적용** | `sudo netplan try` | 설정을 시도하고, 일정 시간 응답 없으면 자동 롤백 (추천) |
| **즉시 반영** | `sudo netplan apply` | 수정한 내용을 즉시 시스템에 반영 |
| **결과 확인** | `ip addr show [인터페이스]` | 설정된 IP가 정상적으로 할당되었는지 최종 확인 |

---

### 4. 네트워크 관리 핵심 명령어 모음

| 목적 | 명령어 |
| --- | --- |
| **네트워크 서비스 상태** | `systemctl status systemd-networkd` |
| **라우팅 테이블 확인** | `ip route` 또는 `netstat -rn` |
| **DNS 질의 상태 확인** | `resolvectl status` |
| **연결 테스트** | `ping -c 3 8.8.8.8` |

### ⚠️ 인프라 운영 주의사항

* **원격 접속 단절**: SSH를 통해 원격으로 설정 중 IP를 변경하고 `apply`를 수행하면 현재 연결이 즉시 끊어집니다. 변경된 IP로 재접속해야 합니다.
* **AWS 환경 과금 알림**:
* AWS EC2 인스턴스에 고정 IP가 필요한 경우 내부 설정을 바꾸기보다 **Elastic IP(탄력적 IP)**를 할당하는 것이 일반적입니다.
* **Elastic IP**는 인스턴스에 연결되어 작동 중일 때는 추가 비용이 거의 없으나, **인스턴스를 종료(Stop)하여 IP만 점유하고 있거나 연결되지 않은 상태로 방치하면 시간당 비용이 청구(유료)**됩니다. 불필요한 IP는 반드시 '릴리스(Release)' 하십시오.

## Netplan 네트워크 관리 개요

Netplan은 YAML 형식을 사용하여 네트워크 인터페이스를 설정합니다. 기존 `/etc/network/interfaces` 방식과 달리 계층 구조를 가지며, 설정 변경 후 `netplan apply` 명령을 통해 즉시 적용할 수 있습니다.

> **주의: 과금 관련 안내**
> AWS 환경에서 Elastic IP(EIP)를 추가로 할당하거나, 멀티 홈(Multi-homed) 인스턴스를 위해 ENI(Elastic Network Interface)를 추가 생성할 경우 **추가 비용이 발생**할 수 있습니다. 특히 할당 후 인스턴스에 연결되지 않은 EIP는 시간당 소액의 미사용 요금이 부과되므로 주의가 필요합니다.

## 1. 다중 IP 할당 (IP Aliasing)

IP Aliasing은 하나의 물리적/논리적 인터페이스에 두 개 이상의 IP 주소를 설정하는 방식입니다. 주로 웹 서버에서 여러 도메인에 각각 다른 IP를 바인딩하거나, 서비스 중단 없이 IP를 전환해야 할 때 사용합니다.

### YAML 설정 (예시: eth0)

Netplan에서는 별도의 가상 인터페이스(예: eth0:0)를 만들지 않고 `addresses` 항목에 리스트 형태로 나열합니다.

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      addresses:
        - 192.168.1.10/24  # 기본 IP
        - 192.168.1.11/24  # 추가 IP (Aliasing)
        - 192.168.1.12/24  # 추가 IP (Aliasing)
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]
      routes:
        - to: default
          via: 192.168.1.1

```

## 2. 네트워크 본딩 (Interface Bonding)

본딩은 두 개 이상의 물리적 NIC(Network Interface Card)를 하나의 논리적 인터페이스로 묶어 **대역폭 확장(Aggregation)** 또는 **결함 허용(Failover)**을 구현하는 기술입니다.

### 본딩 모드(Mode) 주요 유형

| 모드 | 이름 | 특징 |
| --- | --- | --- |
| **0** | **balance-rr** | 라운드 로빈 방식. 대역폭 분산 및 부하 분산 제공. |
| **1** | **active-backup** | 하나의 NIC만 활성화. 장애 발생 시 백업 NIC로 전환 (가장 많이 사용). |
| **4** | **802.3ad** | LACP(Link Aggregation Control Protocol). 스위치 설정 필요. 대역폭 확장. |

### 본딩 구성 절차 및 YAML 작성

물리 인터페이스인 `enp0s3`와 `enp0s4`를 `bond0`로 묶는 설정입니다.

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: no
    enp0s4:
      dhcp4: no
  bonds:
    bond0:
      interfaces:
        - enp0s3
        - enp0s4
      addresses: [10.0.0.100/24]
      parameters:
        mode: active-backup        # 장애 대비 모드 설정
        primary: enp0s3            # 주 인터페이스 지정
        mii-monitor-interval: 100  # 링크 감시 간격 (ms)
      nameservers:
        addresses: [8.8.8.8]
      routes:
        - to: default
          via: 10.0.0.1

```

## 3. 설정 적용 및 검증

작성된 YAML 파일에 문법적 오류가 없는지 확인하고 시스템에 반영합니다.

### 적용 명령

1. **설정 테스트**: `sudo netplan try` (설정에 문제가 있을 경우 120초 후 자동 복구)
2. **설정 적용**: `sudo netplan apply`

### 검증 명령

* **IP 할당 확인**: `ip addr show bond0` 또는 `ip addr show eth0`
* **본딩 상태 확인**: `cat /proc/net/bonding/bond0`
* 현재 어떤 NIC가 `Active` 상태인지, 슬레이브 인터페이스들의 링크가 정상인지 상세 정보를 출력합니다.

## 실무 가이드: YAML 작성 시 주의사항

1. **들여쓰기(Indentation)**: YAML은 들여쓰기에 매우 민감합니다. 탭(Tab) 대신 공백(Space)을 사용해야 하며, 계층 구조가 어긋나면 적용되지 않습니다.
2. **Renderer 선택**: 서버 환경에서는 주로 `networkd`를 사용하며, 데스크탑 환경(GUI)에서는 `NetworkManager`를 사용하도록 설정합니다.
3. **권한 설정**: 설정 파일(`/etc/netplan/*.yaml`)은 보안을 위해 소유자만 읽고 쓸 수 있도록 권한을 관리하는 것이 좋습니다.
