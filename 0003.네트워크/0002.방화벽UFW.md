우분투(Ubuntu)의 기본 방화벽 도구인 **UFW(Uncomplicated Firewall)**는 사용자가 입력한 명령어를 기반으로 내부적으로 복잡한 iptables 규칙을 생성합니다. 사용자가 설정한 방화벽 규칙이 물리적으로 저장되는 위치와 주요 설정 파일들을 정리합니다.

---

## 1. UFW 규칙 저장 파일 경로

사용자가 `sudo ufw allow 80`과 같이 입력한 규칙들은 다음 파일에 텍스트 형태로 저장됩니다.

* **사용자 정의 규칙 파일:** `/etc/ufw/user.rules`
* **IPv6 전용 규칙 파일:** `/etc/ufw/user6.rules`

이 파일들은 시스템이 부팅되거나 UFW 서비스가 재시작될 때 읽어 들여져 실제 방화벽 규칙으로 적용됩니다. `cat` 명령어를 통해 저장된 내용을 확인할 수 있습니다.

```bash
sudo cat /etc/ufw/user.rules

```

---

## 2. 주요 설정 파일 및 디렉토리 구조

UFW의 동작 방식을 결정하는 핵심 설정 파일들은 다음과 같습니다.

| 파일 경로 | 용도 및 설명 |
| --- | --- |
| **/etc/default/ufw** | UFW의 기본 작동 정책(기본 Allow/Deny, IPv6 사용 여부 등)을 설정합니다. |
| **/etc/ufw/before.rules** | 사용자가 정의한 규칙보다 **먼저** 실행되는 규칙입니다. 루프백(lo) 인터페이스 허용 등이 포함됩니다. |
| **/etc/ufw/after.rules** | 사용자가 정의한 규칙 **이후에** 마지막으로 실행되는 규칙입니다. |
| **/etc/ufw/sysctl.conf** | 커널 수준의 네트워크 설정(IP 포워딩 등)을 제어합니다. |

---

## 3. 실습: 설정 파일 직접 확인 및 백업 (GitHub 포맷)

강의 도중 설정이 꼬이는 것을 방지하기 위해 설정 파일을 백업하거나 확인하는 방법입니다.

1. **현재 상태 확인:**
```bash
sudo ufw status numbered

```


2. **설정 파일 백업:** (학원 PC에서 실습 환경을 옮길 때 유용합니다)
```bash
sudo cp /etc/ufw/user.rules ~/user.rules.bak

```


3. **기본 정책 변경:** 만약 외부 접속이 모두 차단된다면 `/etc/default/ufw` 파일 내의 `DEFAULT_INPUT_POLICY="DROP"` 부분을 확인하십시오.

---

## 4. 유료 전환 및 과금 주의사항

* **소프트웨어 비용:** UFW는 리눅스 내장 도구로 **완전 무료**입니다.
* **AWS 네트워크 ACL/보안 그룹과의 차이:** * UFW는 **OS 내부**에서 동작하는 방화벽입니다.
* AWS에는 이와 별개로 인스턴스 외부에서 작동하는 **'보안 그룹(Security Group)'**이 있습니다.
* **주의:** AWS 보안 그룹에서 80번 포트를 열었더라도, UFW에서 80번을 막아버리면 접속이 되지 않습니다. 두 곳 모두 설정해야 함을 잊지 마십시오.


* **리소스 소모:** 과도하게 많은 규칙(수천 개 이상)을 UFW에 등록하면 CPU 부하가 미세하게 증가할 수 있으나, 일반적인 강의 실습 수준에서는 비용이나 성능에 거의 영향을 주지 않습니다.

---
리눅스 환경에서 방화벽이 정상적으로 작동하고 있는지, 그리고 어떤 포트가 열려 있는지 확인하는 방법은 사용하는 도구에 따라 크게 두 가지로 나뉩니다. 우분투에서 주로 사용하는 **UFW**와 리눅스 표준인 **iptables**를 기준으로 정리합니다.

---

## 1. UFW(Uncomplicated Firewall) 활성화 확인

우분투 계열에서 가장 권장되는 확인 방법입니다.

* **상태 확인 명령어:**
```bash
sudo ufw status

```


* **결과 해석:**
* **Status: active**: 방화벽이 현재 작동 중이며 설정된 규칙이 적용되고 있습니다.
* **Status: inactive**: 방화벽이 꺼져 있는 상태입니다. 모든 통신이 허용되거나 커널 기본 정책을 따릅니다.



### 상세 규칙까지 확인하기

단순히 활성화 여부뿐만 아니라, 규칙의 순서와 상세 정보를 보려면 다음 명령어를 사용합니다.

```bash
sudo ufw status numbered

```

> **Tip:** 숫자가 표시되면 `sudo ufw delete [번호]`를 통해 특정 규칙을 쉽게 삭제할 수 있어 관리가 편리합니다.

---

## 2. iptables 시스템 규칙 확인

UFW는 내부적으로 **iptables**를 사용합니다. 더 근본적인 방화벽 상태를 보려면 아래 명령어를 사용합니다.

* **전체 규칙 리스트 확인:**
```bash
sudo iptables -L -n -v

```


* **주요 옵션 설명:**
* `-L`: 규칙 리스트 출력 (List)
* `-n`: IP 주소와 포트 번호를 이름이 아닌 숫자로 표시 (Numeric)
* `-v`: 통과한 패킷 수와 바이트 수 등 상세 정보 표시 (Verbose)



---

## 3. 서비스 프로세스 상태로 확인

방화벽 도구 자체가 시스템 서비스로 잘 돌아가고 있는지 확인하는 방법입니다.

```bash
sudo systemctl status ufw

```

* **Active: active (exited)**: 서비스가 정상적으로 로드되어 규칙이 적용되었음을 의미합니다.

---

## 4. 유료 전환 및 과금 주의사항

* **소프트웨어 요금:** UFW와 iptables는 리눅스 커널 및 기본 패키지에 포함되어 있으므로 **전액 무료**입니다.
* **AWS 환경 주의사항:**
* **이중 보안 구조:** 온프레미스 VM과 달리 AWS EC2는 **'보안 그룹(Security Group)'**이라는 외부 방화벽이 존재합니다.
* OS 내부에서 UFW를 활성화하여 포트를 열었더라도, **AWS 콘솔의 보안 그룹에서 해당 포트가 인바운드 허용**되어 있지 않으면 외부에서 접속이 불가능합니다.
* 보안 그룹 설정 변경은 무료지만, 이를 통해 특정 IP가 아닌 모든 IP(`0.0.0.0/0`)에 대해 위험한 포트(RDP, DB 등)를 개방할 경우 해킹으로 인한 **비정상적 리소스 생성 및 과금**의 원인이 될 수 있으니 주의해야 합니다.
